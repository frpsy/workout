# Repday (일일 운동 체크)

푸시업·풀업·스쿼트(그리고 직접 추가한 운동)를 매일 체크하고, 주마다 목표를 조금씩 늘려 가는 기록장입니다.

- 주소: https://frpsy.github.io/workout/
- 예전 주소(frpsy.github.io/test/workout-check/)와 같은 브라우저라면 기록이 그대로 이어집니다.
- 폰에서 열고 **공유 → 홈 화면에 추가**를 하면 앱처럼 쓸 수 있습니다 (오프라인에서도 열림). 새로 배포되면 앱을 다시 볼 때(운동 시간을 재거나 쉬는 중이면 끝난 뒤에) 한 번 새로 불러와 최신 판이 됩니다(js/main.js 아래쪽 서비스 워커 등록).

## 기능

| 기능 | 설명 |
|---|---|
| 오늘 체크 | 종목별 목표(세트당 개수 × 세트 수, 기본 3세트 예: 15 × 3), 오른쪽 버튼(64×44px, 지금 할 종목만 진하게)을 누를 때마다 한 세트씩만 완료(마지막 세트에서 종목 완료, 모두 마친 뒤에는 연한 ‘완료’ 표시로 바뀌고 더 눌러도 바뀌지 않음, 빠른 더블탭의 두 번째 누름은 무시), 버튼 안에 진행(1/3)과 눌렀을 때 완료될 세트(‘2세트 완료’)를 글자로 보여 주고 목표 옆 점은 마친 세트·다음 세트를 표시만 함(누르는 버튼이 아님), 체크한 세트가 있으면 점 옆에 ↶ 되돌리기 버튼이 나타나 한 세트씩 취소, 세트당 실제 개수(− +는 1씩, 꾹 누르면 5씩 계속, 직접 입력도 가능)와 실제 세트 수 수정. 목표 옆에 작은 원형 세트 체크를 두고 카드 높이를 간결하게 유지 |
| 영상으로 같이하기 | 푸시업·풀업·스쿼트 이름 옆의 작은 유튜브 아이콘(길게 누르면 영상 제목)을 누르면 종목별 유튜브 영상(데스런 홈트레이닝: 푸쉬업 루틴·턱걸이/풀업 5X5·스쿼트 35X3)이 새로 열려 영상을 보며 따라 할 수 있음. 앱 안에 영상을 넣지 않고 유튜브로 열어, 앱을 오가도 영상 소리가 이어짐. 영상은 `js/config.js`의 `EXERCISE_VIDEOS`에서 종목 id별로 추가 |
| 화면 보기 2단계 | 상태 줄 오른쪽의 기본/상세 버튼. 기본은 개수·세트 조절 줄을 접어 종목마다 두 줄로 줄이고(이름·목표·⌄를 누르면 그 종목만 펴고 접음), 상세는 모든 종목의 개수·세트 조절 줄을 보임. 고른 단계는 이 브라우저에 기억(저장 값은 이름을 바꾸기 전과 같아 이미 골라 둔 단계가 그대로 유지되고, 고른 적이 없으면 기본으로 열림) |
| 난이도 3단계 | 오늘 화면의 쉬움/보통/어려움 버튼으로 그날 목표를 0.8·1·1.2배로 바로 조절(초 단위는 5초 단위로 맞춤). 그날 기록에만 남고 이미 완료한 종목의 목표는 그대로 |
| 운동시간 | 오늘 화면 위쪽 ▶ 운동 시작을 누르면 시간이 흐르고, 중지/재개로 잠시 멈출 수 있고(멈춘 시간은 제외), ■ 종료를 누르면 그날 총 운동시간에 더해 기록(같은 날 여러 번이면 합산). 취소는 바로 기록 없이 버립니다. 오늘 기록된 운동시간은 ‘시간 초기화’로 바로 지울 수 있습니다(지난 날에는 버튼이 없음). 오늘 체크한 세트·완료를 모두 되돌리면(체크가 하나도 없는 상태) 재던 시간과 기록된 운동시간도 함께 초기화됩니다. 새로고침·앱 재실행 뒤에도 이어서 재며, 기록 탭에서 오늘·최근 7일 운동시간과, 날짜를 눌러 그날 시작–종료 시각(구간)을 확인(시각은 이 기능 이후 잰 날부터 남음). 아직 재는 중이면 그날 카드에 ‘운동 중’으로 보임(■ 종료해야 합산) |
| 운동 한 번 더 하기 | 전체 세트 완료 또는 운동시간 ‘종료’ 후 ‘운동 한 번 더 하기’ 버튼이 나타납니다. 목표를 전부 채우지 않았어도 한 회차를 종료할 수 있으며, 달성률은 실제 완료 세트를 기준으로 유지합니다. 누르면 새 운동 회차와 스톱워치를 시작하고 세트 체크를 초기화합니다. 이전 회차의 세트 기록과 시작·종료 시간 및 하루 누적 운동시간은 유지합니다. 기록 탭에서 각 회차의 세트를 펼쳐 볼 수 있습니다. |\n| 하루 여러 번 운동 | 아침·저녁 구분 없이 하루 기록 하나에 체크하고, 운동은 ▶ 운동 시작·■ 종료를 누를 때마다 시작–종료 시각 구간으로 쌓여(하루에 여러 번 가능) 기록 탭 카드에 ‘07:10 – 07:40, 21:00 – 21:20’처럼 모두 보이고 총 운동시간은 합산. 오늘 첫 세트를 마치면 운동 시작을 대신 눌러 주지만, 오늘 이미 운동시간을 기록했으면 두 번째부터는 ▶ 운동 시작을 직접 누름. 예전에 따로 저장한 저녁 기록(`pm`)은 읽을 때 하루 기록에 합쳐짐(종목마다 마친 쪽 우선) |
| 오늘의 마무리 | 전체 세트 완료 또는 운동시간 ‘종료’ 후 오늘 화면에 접힌 한 줄 ‘오늘의 마무리 쓰기’ 버튼이 나타나고, 누르면 ‘운동 소감’과 ‘감사한 일 한 가지’ 한 줄 칸이 펼쳐짐. 마지막 종목을 막 체크하면 그 줄이 화면으로 올라옴(포커스는 그대로, 앱을 열어 기록을 불러올 때는 움직이지 않아 화면이 맨 위에서 시작). 쓰는 대로 저장(기기·계정 동기화 포함, 각 200자), ‘완료’를 누르면 짧게 접혀 보이고 접힌 내용이나 연필 버튼을 누르면 다시 씀. 쓰다가 ‘나중에’를 누르면 다시 한 줄로 접음. 기록 탭에서 날짜를 누르면 그날 카드에 소감·감사가 함께 보임 (js/ui/journal.js, js/ui/history.js) |
| 휴식 타이머 | 오늘 화면의 한 줄 타이머(화면 크기와 상관없이 늘 탭 막대 바로 위에 붙어 있어 스크롤 없이 누름): 시간 숫자를 누르면 30·60·90초 프리셋 3단계로 바로 바뀌고, −15/+15초로 세밀하게 조절(15초~10분, 마지막 값 기억) 후 시작·중지. 왼쪽 ‘휴식 자동/수동’ 버튼으로 세트를 체크할 때 휴식이 자동 시작되게 할 수 있음(기본 자동, 되돌릴 때와 모든 운동을 마쳤을 때는 시작 안 함, 오늘 체크를 모두 되돌리거나 모든 운동을 마치면 쉬는 중이던 휴식도 조용히 멈춤). 쉬기 전에는 한 줄(48px)이고, 쉬는 동안은 어두운 바탕의 큰 줄(64px, 숫자 40px)로 바뀌어 멀리서도 읽힘. 쉬는 동안 줄 아래쪽의 얇은 막대(3px, 숫자·버튼을 가리지 않음)가 남은 시간만큼 끊김 없이 부드럽게 줄어들고(애니메이션 하나로 흘려보내고, 시간을 바꾸면 새로 시작, 움직임 줄이기 설정이면 단계로 갱신) 마지막 3초는 숫자·막대가 주황으로 바뀌고 1초마다 숫자가 살짝 튐. 끝나면 소리·진동과 함께 타이머 줄 전체가 같은 높이의 초록으로 바뀌고(종 표시) 화면 가장자리가 두 번 번쩍이며 ‘휴식 끝 +0:07’처럼 지난 시간을 1분 동안 보여 줌(시간을 누르면 닫히고, 다음 휴식을 시작해도 걷힘). 쉬는 중에 새로고침·앱 재실행(새 배포 자동 반영 포함)을 해도 남은 시간이 이어지고, 그사이 끝났으면 다시 열 때 알리며 1분 넘게 지난 휴식은 조용히 정리. 실행 중에는 화면이 꺼지지 않게 요청 |
| 화면 색 | 설정 맨 위 ‘화면 색’에서 자동·라이트·다크를 고름(이 기기에 기억). 자동은 기기 설정을 따르되, 앱을 오가는 순간 잠깐 어둡게 읽히는 값에는 흔들리지 않게 첫 화면이 그려지기 전에 `<html data-theme>`을 정하고(`index.html`), 값이 바뀌어도 0.4초 기다렸다가 화면이 보일 때 한 번만 다시 읽음(`js/theme.js`) |
| 효과음 | 기본은 다른 앱(유튜브·음악)의 백그라운드 재생을 멈추지 않고 그 위에 섞여 나는 소리(Audio Session `ambient`, 앱을 여는 순간부터 적용). 설정의 ‘무음 모드에서도 효과음’을 켜면 무음 스위치와 상관없이 소리가 나는 대신 다른 앱 소리가 멈출 수 있음. 세트 체크(세트 번호에 따라 음이 올라감)·종목 완료·모두 완료·되돌림·운동 시작/종료·휴식 타이머 시작·중지음, 끝나기 3초 전 3·2·1 카운트, 끝나면 세 번 알림음(세트 체크로 자동 시작될 때는 시작음 없이). 파일 없이 Web Audio로 만들고, 상태 줄의 스피커 버튼으로 켜고 끄며 이 브라우저에 기억. 아이폰은 무음 스위치가 켜져 있으면 소리가 나지 않을 수 있음 |
| 모바일 | 홈 화면 앱에서 iOS 26 이후 맨 위가 뿌옇게 흐려지는 시스템 효과를 막기 위해, 상태 표시줄보다 조금 더 내려온 불투명한 고정 덮개(`index.html`의 `.topcap`, 배경색과 같음)를 둠(가상 요소나 눌리지 않는 요소는 WebKit이 알아보지 못함). 조작부(종목 카드·타이머·머리말 버튼)에서는 손가락이 옆으로 미끄러져도 옆 탭으로 넘어가지 않고(빈 곳을 밀면 넘어감), 내용이 화면에 딱 맞을 때 화면 전체가 끌려가지 않음. 기본 보기는 아이폰 SE(320×568)부터 큰 아이폰까지 쉬는 중에도 스크롤 없이 한 화면에 들어옴(상세는 작은 폰에서 조금 스크롤되고 휴식 타이머는 탭 막대 위에 고정). 더블탭 확대 지연 제거(touch-action), 입력 칸·메모 칸 16px(iOS 포커스 확대 방지), 난이도·화면 보기·효과음·자동휴식·되돌리기 버튼의 눌리는 영역을 44px 안팎으로 넓힘, 세트 완료는 큰 버튼 하나로, 운동 시작·종료·중지·취소·휴식 시작 버튼은 보이는 높이 36px, 가끔 쓰는 개수·세트 − +와 휴식 ±15는 32px에 누르는 영역만 44px, 누르는 즉시 살짝 눌리는 반응, 안전 영역(노치)·홈 화면 앱 지원 |
| 앱 같은 화면 | 아래 탭 3개(오늘 / 기록 / 설정). 오늘은 체크·스톱워치·휴식 타이머만, 기록은 기본 이번 주 한 줄 달력(‘한 달 보기’를 누르면 달 단위 달력으로 펼쳐지고 ‹ › 버튼으로 달 이동, 기록이 시작된 달~이번 달) → 날짜를 누르면 바로 아래 카드에 그날 총 운동시간·시작–종료 시각·종목별 한 것·마무리 소감(‘이 날 기록 고치기’로 오늘 탭 이동)과 그 아래 달성·연속·종목별 꾸준함·앞으로 4주 목표, 설정은 무음 모드 효과음·계정·목표·운동 목록. 달력에서 날짜를 누르면 오늘 탭으로 가서 그날 기록을 고침. 탭은 주소 뒤 #record 로 남아(예전 #log·#stats 도 기록으로 열림) 새로고침·뒤로 가기에도 유지. 세 화면이 가로로 나란히 붙어 있어 옆으로 밀면(오늘 화면의 버튼·조절 칸·타이머 위에서는 제외) 옆 화면이 함께 따라오고, 손을 떼면 관성대로 한 화면씩 붙음(토스 앱처럼, 브라우저 기본 가로 스크롤·스냅). 화면마다 세로 스크롤 위치를 따로 기억하고, 아래 탭 버튼을 누르면 미끄러지지 않고 바로 전환. 넘기는 도중에도 아래 탭 표시가 따라 바뀌고, 탭 위 짧은 막대는 미는 만큼 옆 탭 쪽으로 미끄러짐. 보이지 않는 화면은 inert로 탭 키·화면 읽기에서 건너뜀. 운동 시간을 재는 동안(중지 중 제외) 화면이 꺼지지 않게 요청 |

## Firebase로 기기 간 저장 켜기

기본은 브라우저 저장입니다. 아래를 하면 로그인한 계정에 저장되어 폰·PC가 같은 기록을 봅니다. 설정이 없으면 지금처럼 동작합니다.

1. [Firebase 콘솔](https://console.firebase.google.com)에서 프로젝트를 만들고 **웹 앱**을 추가해 `firebaseConfig`를 확인합니다.
2. **Authentication → 로그인 방법**에서 Google을 켭니다. **설정 → 승인된 도메인**에 `frpsy.github.io`가 있는지 확인합니다 (기본 포함).
3. **Firestore Database**를 만들고(프로덕션 모드), **규칙**에 `firestore.rules` 내용을 붙여 게시합니다.
4. `js/firebase-config.js`의 `FIREBASE_CONFIG`에 1의 값을 붙여 넣고 커밋합니다. 이 값은 공개 식별자이며 데이터는 규칙이 지킵니다.
5. 앱 → 설정 → 계정 → **Google로 로그인**. 처음 로그인하면 이 브라우저의 기록이 계정으로 옮겨집니다 (계정에 기록이 이미 있으면 옮기지 않고 계정의 기록이 보입니다).

Firebase SDK는 `scripts/firebase-entry.js`를 묶어 `js/vendor/firebase.js`로 커밋해 둡니다 (오프라인에서도 동작). SDK 버전을 올렸다면 `npm run build:firebase`를 다시 실행하세요. CI가 최신 여부를 검사합니다.

- **증가 방식 추가**: `js/progression.js`의 `LEVEL_RULES`에 함수 추가 후 설정 화면 라디오 추가
- **저장소 추가** (예: Firebase로 기기 간 동기화): `js/storage/`에 같은 모양의 어댑터를 만들고 `storage/index.js`의 `createStorage()`에 연결
- **앱 파일 추가·삭제**: `npm run sw`로 `sw.js`의 `ASSETS`를 다시 만들기 (안 맞으면 `npm test`가 실패). 캐시 이름은 배포할 때 CI가 파일 내용으로 자동으로 정합니다. 글꼴은 `fonts/`에 있고 아티팩트 빌드만 Google Fonts를 씁니다
- **스타일 고치기**: 글자 크기는 `--fs-*`, 그림자는 `--shadow-*` 변수만 씁니다(`npm test`가 검사). 어두운 테마 색은 `style.css`의 두 블록(기기 설정·`data-theme`)에 똑같이 넣습니다(테스트가 같은지 검사). 화면이 바뀌면 안 되는 정리는 `npm run shots`로 확인합니다
- **저장 형식 변경**: `SCHEMA_VERSION`을 올리고 `model.js`의 `normalize*`에서 이전 형식을 변환

## 개발

Node.js 24.12 이상을 사용합니다 (`.nvmrc`: 24, CI도 Node 24).

```bash
npm install
npm run lint             # ESLint
npm test                 # 테스트
npm run sw               # sw.js 미리 저장 목록 갱신
npm run build:artifact   # dist/artifact.html 생성
npx serve .              # 로컬 확인 (모듈 스크립트라 file://로는 안 열림)
npm run shots            # 화면 비교: 지금 폴더 vs origin/main (다른 커밋은 -- --base <커밋>)
npm run check:iphone     # 아이폰 점검(WebKit, 가짜 시계): 실패가 있으면 종료 코드 1, -- --shots면 shots/iphone/에 단계별 화면 저장
```

`npm run shots`는 화면이 바뀌면 안 되는 스타일 정리를 확인할 때 씁니다. 폭 390·320px(키 640px), 밝은·어두운 테마, 오늘(상세·기본·모두 마침·운동 중·중지)·기록·설정 화면을 첫 화면과 전체로 찍고(48장), 같은 장면에서 모든 요소(숨은 요소·::before·::after 포함)의 계산된 스타일도 비교합니다. 320px은 움직임 줄이기 설정으로 찍습니다. 시각(2026-10-28 수요일 19:30, 서울)·난수·5주치 기록을 고정하고 Firebase·날씨 요청은 막습니다. 결과는 `shots/`(`base/`·`head/`·`diff/`, 커밋 안 함)에 남고 다른 그림이 있으면 종료 코드 1입니다. Playwright 크로미움이 필요합니다(`npx playwright install chromium`).

`npm run check:iphone`은 화면을 바꾸는 작업 뒤에 쓰는 사용 흐름 점검입니다. 아이폰 SE(320×568)·13(밝은·어두운)·15 Pro Max를 WebKit으로 흉내 내, 시작 화면 걷힘 · 가로 넘침 · 기본/상세 보기 차이와 기본의 한 화면 · 세트 체크로 휴식 자동 시작 · 쉬는 중 타이머 크기와 3px 진행 막대(버튼을 가리지 않음) · ±15 · 마지막 3초 · 끝남(높이 그대로) · 새로고침 뒤 이어짐 · 모두 마친 뒤 휴식 정지와 접힌 오늘의 마무리 · 맨 위 덮개 · 탭 이동 · 자바스크립트 오류를 확인합니다(88개). 화면 규칙을 일부러 바꾸면 해당 항목이 실패하는지로 점검 자체를 믿을 수 있게 했습니다. 실제 기기의 합성·소리·진동은 대신하지 못하므로 큰 변경 뒤에는 기기에서도 한 번 봅니다. Playwright WebKit이 필요합니다(`npx playwright install webkit`).
